# Исправление списка статей — SPA, пагинация и SSR/prerender

## Что изменено

- Список `/articles` больше не рендерится из Pinia как побочный эффект `useAsyncData`.
- Данные списка теперь берутся напрямую из `useAsyncData`/Nuxt payload.
- SSR и prerender продолжают отдавать готовый список статей в HTML/payload.
- При SPA-переходах между `/articles`, `/articles/page2`, `/articles/page3` выполняется обновление списка по текущему URL.
- При изменении фильтров/поиска список обновляется без перезагрузки страницы.
- Пагинация использует `totalPages`, рассчитанный непосредственно из ответа `/api/articles`.
- Для несуществующей страницы пагинации сохранён настоящий 404 как при прямом запросе, так и при SPA-переходе.
- Фильтры загружаются через Nuxt payload и затем синхронизируются в Pinia — они больше не зависят от выполнения side-effect callback.
- Во время клиентского обновления показывается лёгкий skeleton вместо старых статей предыдущей страницы.
- Первые 3 изображения карточек статей получают `loading=eager` + `fetchpriority=high`; остальные — `loading=lazy`, `fetchpriority=auto`, `decoding=async`.
- Источники/домены изображений статей НЕ менялись. Перенос `mail.daigo.ru` в S3 делается отдельной задачей позже.
- Исправлен boolean `modelValue` в фильтрах статей, чтобы `BaseCheckbox` не получал `undefined`.

## Ожидаемое поведение

1. Переход с любой страницы сайта на `/articles` без F5 сразу показывает статьи.
2. Переход `/articles` → `/articles/page2` меняет и URL, и набор статей.
3. Переход обратно на page1 также обновляет список без перезагрузки.
4. Фильтры и поиск обновляют список без F5.
5. Прямой заход/F5 сохраняет SSR/prerender.
6. `/articles/page9999` возвращает 404.

## Изображения

Домены и URL изображений не менялись. Текущие `mail.daigo.ru`/S3 URL остаются как есть до отдельного переноса изображений статей.
