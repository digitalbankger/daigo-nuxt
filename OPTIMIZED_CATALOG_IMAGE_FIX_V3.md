# Исправление optimized-изображений каталога v3

Причина оставшихся пропусков: серверный `/api/shop/products` нормализовал исходный S3 URL в `/media-s3/...` до передачи карточке. Генератор build-time optimized-файлов строит физический путь из исходного URL, поэтому для части товаров восстановление исходного host/bucket было неоднозначным.

Исправление:
- API каталога теперь дополнительно возвращает `imageSource` и `detailImageSources` в исходном виде;
- отображаемый `image` остаётся нормализованным и совместимым с текущим `/media-s3/`;
- `ProductCard` передаёт в `CatalogCardImage` исходный URL, поэтому optimized candidate строится точно тем же алгоритмом, что и генератор;
- при ошибке optimized-файла fallback по-прежнему идёт на нормализованный исходник, затем на placeholder.

Повторная генерация существующих optimized-файлов не требуется, если они уже были созданы текущим `generate-optimized-images.mjs`.
